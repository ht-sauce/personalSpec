# writing-conventions · SPEC 文档书写约定

> 适用于根目录两份产品 SPEC 及其未来新增的形态接入件。

## 1. 语言

- 正文一律简体中文；代码、字段名、命令、技术名词保留原文。
- 不为自明内容加注释；禁止 `TODO` / `FIXME` / `// removed` 类占位。

## 2. 版本与修订记录

- 文档头部标注 `SPEC 模板 vX.Y`：X 为结构性修订（章节体系、适用范围变化），Y 为增补修订。
- 形态接入件版本独立，但头部必须写明所对接的主模板版本（如「对接《通用项目建项规范-SPEC v2.0》」）。
- 每次修订必须留痕：版本号 + 日期 + 修订要点；大版本单列修订分析章节。
- 历史修订分析、否决专区、superseded 的 ADR **只增不删**。

## 3. 占位符

- `[项目名]`：复制模板后替换的文本占位符，方括号为半角。
- `【可选项】` / 【冻结】：给维护者看的中文标注，使用全角方括号。
- 两类占位符不得混用；交付给用户的成品文档中不得残留未处理的占位符。

## 4. 硬约束条目写法

- 编号连续（形态接入件用 `HC-Dn` 形式），每条写清「**约束 + 违反后果**」。
- 准入标准：**写边界，不写偏好**——只收违反会导致功能异常 / 数据事故的边界，或已明确否决并验证过后果的做法。
- 「遵循最佳实践」类空话、ESLint 等工具能拦截的风格问题，不进硬约束清单。

## 5. 图表与表格

- 图表统一 Mermaid，保证常见 Markdown 渲染器直接出图。
- 文档表格手工维护对齐；引入 Prettier 时以 `.prettierignore` 忽略 `*.md`，禁止重排中文表格。

## 6. 文件引用

- 同目录文件：《文件名》形式相对引用（如《原型设计规范-SPEC.md》），不写绝对路径。
- 主模板末尾的回填位置是唯一允许的绝对路径锚点，文件迁移后必须立即修正。

## 7. 结构纪律

- 主模板按「章（§n）」组织，形态接入件按「条（§x.y）」组织并显式标注替换 / 追加的主模板章节号。
- 新增章节导致后续编号变化时，全库交叉引用（接入件、AGENTS.md、skill）在同一批改动中更新。
