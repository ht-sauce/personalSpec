# docs/README · personalSpec 项目治理入口

> 本文件只管 **personalSpec 这个项目本身**（规范资产库的维护）。产品 SPEC 的规则全文在根目录两份 SPEC，不在此复制。

## 1. 必读流程（接需求强制第一步）

1. Read 根目录 [AGENTS.md](../AGENTS.md)（统一入口）+ 本文件硬约束。
2. 修改产品 SPEC：通读对应 SPEC 全文 + [writing-conventions.md](writing-conventions.md)。
3. 定位文件先查 [project-overview.md](project-overview.md)，禁止全量扫描。
4. 按主模板 §3 工作流执行：读规范 → 理解需求 → 探索现状（只读）→ 方案对照 → 一次性批量改动 → 验证 → 汇报。
5. 例外：单行 typo / 单行修复可简化，但仍须遵守硬约束。

## 2. 硬约束清单

**通用条目（本项目适用）**

1. **先读文档再动手**：未完成必读流程不得改文件。
2. **先对话后改动**：方案确认后一次性批量执行，禁止边读边改、边对话边改。
3. **不主动创建文档**：除本规范体系已声明的文件外，不得新建 `*.md`，除非用户明确要求。
4. **禁止全量扫描**：先查文件地图，只精读目标文件。
5. **不一致先裁决**：发现各 SPEC 之间、SPEC 与治理文档之间不一致时，先报告用户裁决，不得静默采信任何一方。
6. **执行卡顿须中断换路**：思考或命令执行停滞超过 5 分钟必须中断当前方式并改换路径（缩小范围 / 换命令 / 换工具 / 向用户说明卡点），禁止死等命令。

**本项目特有条目**

7. **主模板唯一**：通用规则只写在《通用项目建项规范-SPEC》中；形态接入件**只写差异**，禁止复制通用骨架（违反：多处维护失真）。
8. **交叉引用同批更新**：形态接入件与附录必须显式标注承接 / 替换的主模板章节号；主模板章节编号变化时，全库交叉引用（形态接入件、附录、AGENTS.md、README、docs/）在同一批改动中更新。
9. **修订留痕**：产品 SPEC 的每次改动必须在其修订记录 / 版本信息中留痕（版本号、日期、要点）；历史修订分析只增不删；否决专区与 superseded 的 ADR 默认保留，防翻案价值消失且经用户确认后可整体清理，清理须留痕。
10. **引用用相对锚点**：同目录文件引用写《文件名》，不写死易漂移的绝对路径；唯一例外是主模板末尾的回填位置锚点，路径变更时必须同步修正。
11. **回填义务**：外部项目使用模板沉淀的新约束、新形态，必须回填到对应 SPEC，不得只留在单个项目里。

## 3. 维护契约（改动 → 必须同步对照表）

| 场景 | 必须同步更新 |
| --- | --- |
| 主模板章节编号 / 结构变化 | 形态接入件与附录交叉引用 + 根 AGENTS.md 索引 + README + project-overview |
| 新增 / 修改形态接入件 | 根 AGENTS.md 索引 + 主模板适用范围章节 + README 资产清单 + project-overview |
| 硬约束 / 问项条目增删改 | 对应 SPEC 修订记录 |
| 本项目新增 / 删除文件或文件用途变化 | project-overview（同批，强制） |
| Git 提交规则变化 | .trae/rules/git-commit-message.md + 主模板 §4 |
