# docs/README · personalSpec 项目治理入口

> 本文件只管 **personalSpec 这个项目本身**（规范资产库的维护）。产品 SPEC 的规则全文在根目录两份 SPEC，不在此复制。

## 1. 必读流程（接需求强制第一步）

1. Read 根目录 [AGENTS.md](../AGENTS.md)（统一入口）+ 本文件硬约束。
2. 修改产品 SPEC：通读对应 SPEC 全文 + [writing-conventions.md](writing-conventions.md)。
3. 定位文件先查 [project-overview.md](project-overview.md)，禁止全量扫描。
4. 按主模板 §8 工作流执行：读规范 → 理解需求 → 探索现状（只读）→ 方案对照 → 一次性批量改动 → 验证 → 汇报。
5. 例外：单行 typo / 单行修复可简化，但仍须遵守硬约束。

## 2. 硬约束清单

**通用条目（本项目适用）**

1. **先读文档再动手**：未完成必读流程不得改文件。
2. **先对话后改动**：方案确认后一次性批量执行，禁止边读边改、边对话边改。
3. **不主动创建文档**：除本规范体系已声明的文件外，不得新建 `*.md`，除非用户明确要求。
4. **禁止全量扫描**：先查文件地图，只精读目标文件。
5. **不一致先裁决**：发现产品 SPEC 之间、SPEC 与 skill 之间不一致时，先报告用户裁决，不得静默采信任何一方。

**本项目特有条目**

6. **主模板唯一**：通用规则只写在《通用项目建项规范-SPEC》中；形态接入件**只写差异**，禁止复制通用骨架（违反：多处维护失真）。
7. **skill 不复制规则**：全局 skill 只指向 SPEC 路径与章节号；主模板章节结构变化时，同批更新 skill 与 AGENTS.md 索引。
8. **修订留痕**：产品 SPEC 的每次改动必须在其修订记录 / 版本信息中留痕（版本号、日期、要点）；历史修订分析、否决专区、superseded 的 ADR 只增不删。
9. **引用用相对锚点**：同目录文件引用写《文件名》，不写死易漂移的绝对路径；唯一例外是主模板末尾的回填位置锚点，路径变更时必须同步修正。
10. **回填义务**：外部项目使用模板沉淀的新约束、新形态，必须回填到对应 SPEC，不得只留在单个项目里。

## 3. 维护契约（改动 → 必须同步对照表）

| 场景 | 必须同步更新 |
| --- | --- |
| 主模板章节编号 / 结构变化 | 形态接入件交叉引用 + `project-spec-init` skill + 根 AGENTS.md 索引 + project-overview |
| 新增 / 修改形态接入件 | 根 AGENTS.md 索引 + 主模板适用范围章节 + skill 形态分流 + project-overview |
| 硬约束 / 问项条目增删改 | 对应 SPEC 修订记录 |
| 本项目新增 / 删除文件或文件用途变化 | project-overview（同批，强制） |
| Git 提交规则变化 | .trae/rules/git-commit-message.md + 主模板 §9 |
